# “记忆通行证”界面设计方案

> 文档类型：独立 UI 设计方案
> 适用产品：FoloToy AI Passport  规范对应页：[English](memory-training-ui-plan.md)
> 目标版本：离线 MVP  评审状态：已实现基线

## 1. 设计结论

“记忆通行证”是一个聚焦的产品外壳，包含开机界面、`Memory / Settings / Exit` 三项主菜单和一个顺序记忆玩法。用户只需理解一件事：先看并听设备播放的 `UP / DOWN / OK` 序列，再按同样顺序复现。初始序列长度为 3，每次完整答对后重新生成一串长度增加一项的随机序列，最多到 12；答错或单步超时结束。最高成绩是本地保存的“完整复现过的最高序列长度”，不是联网排名，也不是医疗或认知能力评估。

首版画面全部复用 `ui_pixel` 的天空、草地、标题牌、墨色描边面板和电视机器人。屏上以大图形和英文短词为主：当前固件只带 Montserrat 14/20，未提供中文字形；不要为了这一页临时塞入完整 CJK 字库。中文文案是本文档和开发注释，设备上使用 ASCII、箭头和颜色加文字的组合。

## 2. 已确认的约束与假设

| 项目 | 设计约束 |
| --- | --- |
| 显示 | ST7789P3 240 × 320，竖屏 RGB565；布局使用固定像素和局部刷新，不依赖触摸或 MISO。 |
| 内存 | ESP32-C3 无 PSRAM；不创建整屏双缓冲、不缓存整段 PCM。序列最多 12 个三值 token，可用小型静态数组。 |
| 输入 | GPIO0 ADC 电阻梯产生 `UP`、`DOWN`、`OK`；逻辑输入优先消费 `PRESS`，仅在驱动不提供 `PRESS` 时回退到 `CLICK`。 |
| 全局导航 | 菜单中 `UP/DOWN CLICK` 移动，`OK CLICK` 进入；功能页 `OK LONG` 由全局路由拦截并返回菜单。 |
| 音频 | ES8311 播放为阻塞 API，必须由音频工作任务消费事件；音频不可用时玩法仍可完整进行。 |
| 电池 | CW2017 是可缺省能力；有读数时显示在右上角云朵下方的空闲天空区，读数为 `-1` 时隐藏而不是显示伪数字。 |
| 持久化 | 使用现有 NVS 分区，不新增分区；只保存 `best_level`（0–12）及必要的版本信息。 |
| 随机序列 | 每局开始生成完整的长度 3 序列；答对后按下一长度重新生成完整序列，不继承上一轮顺序或前缀。token 独立抽取，相邻重复属于有效随机结果。随机种子不持久化。 |
| 产品外壳 | 开机界面后进入 `Memory`、`Settings`、`Exit` 主界面；`Memory` 使用主卡片，两个工具入口使用次级卡片。设置提供亮度（25/50/75/100%）、声音（开/关）和节奏（慢/标准/快）；首版只在本次运行内生效。 |
| 状态信息 | 系统时钟有效时显示 `HH:MM`；没有 RTC/NTP 时从 `00:00` 显示设备运行时间；电量计可读时显示百分比，不可用时显示 `--%`。 |
| 计分口径 | `level` 是正在挑战的序列长度；`clear_level` 是完整复现的最后长度；`best_level = max(best_level, clear_level)`。 |
| 目标人群 | 普通成人为默认节奏，兼顾老人易读、易听、易恢复；不做医疗宣称，不把成绩解释为健康指标。 |

## 3. 信息架构

```text
开机界面
  └─ 主界面：MEMORY / SETTINGS / EXIT
      ├─ MEMORY（记忆通行证）
      │   └─ READY
      ├─ SETTINGS（亮度 / 声音 / 节奏）
      └─ EXIT（安全关机提示）
          └─ OK 短按 → PLAYBACK（设备播放序列）
              └─ 播放完 → INPUT（用户复现）
                  ├─ 全部正确 → SUCCESS → 下一长度 PLAYBACK
                  ├─ 答错 → RESULT / WRONG
                  └─ 单步 5 秒无输入 → RESULT / TIME UP
              └─ 长按 OK（任意功能状态）→ 返回主菜单
          └─ 成功完成长度 12 → RESULT / MAX CLEAR
```

首版不单独建立“成绩页”：`BEST` 常驻 READY 和 RESULT，避免让用户在训练前后再穿越一层菜单。设置页只保留亮度、声音和播放节奏，不提供暂停、重播正确答案、用户档案或联网流程。

## 4. 页面与状态

玩法只有一个 screen，状态机决定同一套控件的文案、颜色和可用输入。状态切换由纯逻辑模型决定，LVGL 只负责呈现。

| 状态 | 屏幕重点 | 进入/离开 | 按键与计时 |
| --- | --- | --- | --- |
| `READY` 准备 | `MEMORY`、`BEST n`、三枚按键图例、`OK START`、`HOLD OK BACK` | 进入页面、重试前、结果停留后 | `OK CLICK` 开始；`UP/DOWN CLICK` 不改变设置，只做轻微确认反馈；`OK LONG` 返回。停留不超时。 |
| `PLAYBACK` 播放 | `LEVEL n/12`、`WATCH`、当前 token 高亮、`i/n` 进度 | READY 开始或 SUCCESS 后自动进入 | 忽略普通按键，避免用户抢答；`OK LONG` 仍可退出。每个 token 亮起约 360 ms，间隔约 160 ms。 |
| `INPUT` 复现 | `LEVEL n/12`、`YOUR TURN`、`i/n`、三个大按键卡片、进度点 | 播放完成后立即进入 | 每个预期 token 给 5 秒；正确按键立即反馈并进入下一格；错误立即结束；`OK LONG` 返回；`DOUBLE` 不产生额外输入。 |
| `SUCCESS` 本轮通过 | `GOOD`、`CLEAR n`、短暂全屏/面板绿闪、机器人跳一下 | INPUT 全部正确 | 锁定输入约 900 ms；`n < 12` 重新生成下一长度的完整随机序列并进入 PLAYBACK；`n = 12` 进入 MAX RESULT。 |
| `RESULT` 结束 | `WRONG` 或 `TIME UP`、`CLEAR n`、`BEST n`、`TRY AGAIN`、`HOLD OK BACK` | 错误、超时或最高等级完成 | `OK CLICK` 开始新会话（先显示 500 ms READY cue，再播长度 3）；`UP/DOWN CLICK` 不改变成绩；`OK LONG` 返回。结果不自动消失。 |
| `MAX RESULT` | `MAX CLEAR`、`12/12`、`BEST 12` | 完整通过长度 12 | 与 RESULT 相同；不生成长度 13。 |

### 4.1 成绩显示的明确口径

- 首轮长度为 3；若在首轮出错，显示 `CLEAR 0`、`FAILED AT 3`，不会把未完成的 3 记为最佳。
- 若完成长度 3 后在长度 4 出错，显示 `CLEAR 3`、`FAILED AT 4`。
- 每轮成功先更新 RAM 中的 `clear_level`；只在会话结束且产生新纪录时请求 NVS 写入。
- `BEST 12` 表示已完整复现长度 12，达到首版上限；不显示百分比或“智力等级”。

## 5. 240 × 320 布局草案

坐标是设计基线而非必须逐像素照抄；控件尺寸应保持稳定，便于单 DMA 局部刷新。

```text
 y=0   ┌──────────────────────── 240 ────────────────────────┐
       │  [MEMORY 标题牌]                         [电量]     │  8–44
       │                                                      │
 y=54  │  ┌──────────────────────────────────────────────┐  │
       │  │ LEVEL 4/12                 BEST 7             │  │  62–84
       │  │                 WATCH / YOUR TURN             │  │  88–116
       │  │   ┌──────┐       ┌──────┐       ┌──────┐       │  │
       │  │   │  UP  │       │ DOWN │       │  OK  │       │  │  124–182
       │  │   │  ↑   │       │  ↓   │       │  ●   │       │  │
       │  │   └──────┘       └──────┘       └──────┘       │  │
       │  │                 ● ● ○ ○                        │  │  190–208
       │  │                         HOLD OK BACK           │  │  214–226
       │  └──────────────────────────────────────────────┘  │
 y=238 │                    [电视机器人]                    │
 y=286 │  草地底栏（沿用 ui_pixel_screen_create）            │
 y=320 └──────────────────────────────────────────────────────┘
```

- 外壳：调用 `ui_pixel_screen_create("MEMORY")`，保留固定云朵（约 `x=188,y=8`）、草地（`y=286` 起）和标题牌。
- 主面板建议 `x=12,y=54,w=216,h=178`，沿用 `ui_pixel_panel_create()` 的 4 px 墨边、右下硬阴影和内边距；不要把面板再嵌套成卡片套卡片。
- 三枚按键卡片建议等宽约 58–60 px、最小点击视觉区域 56 × 44 px，位置约 `x=18/88/158,y=124`。卡片同时显示文字和箭头/圆点，不依赖颜色识别。
- 进度点只表示已输入数量，不显示 token 内容，防止无意中泄露答案；最多 12 个点分两行或缩成 8 px 方块。
- 吉祥物沿用 `ui_pixel_mascot_create()`，放在 `y≈238`；成功时调用现有 jump 动效，错误时不让它快速抖动。
- 电量信息放在云朵下方的天空空隙（建议 `y=22–38`，必要时只显示 16 px 图标）；不可覆盖云朵，也不要把电量作为训练主信息。

### 5.1 各状态的内容差异

| 区域 | READY | PLAYBACK | INPUT | RESULT |
| --- | --- | --- | --- | --- |
| 顶栏 | `BEST n` + 时间/电量 | `LEVEL n/12` + `WATCH` | `LEVEL n/12` + `YOUR TURN` | `CLEAR n` + `BEST n` |
| 中央 | 静态三键图例 | 只有当前 token 卡片高亮 | 按下的卡片短暂高亮 | 原因词（`WRONG`/`TIME UP`） |
| 底栏 | `OK START` | `i/n` | `i/n` + 进度点 | `TRY AGAIN` |
| 吉祥物 | 眨眼 | 播放起始轻微跳动 | 每次有效输入轻微跳动 | 只做一次结果动作 |

## 6. 三键交互规范

### 6.1 事件优先级

1. `OK LONG` 是全局返回，优先级高于玩法动作。
2. 训练输入只认一个“逻辑按下”：优先 `PRESS`，或在没有 `PRESS` 的驱动版本中使用 `CLICK`。
3. 同一物理动作产生的 `PRESS + CLICK` 不得计为两个 token；可沿用 `origin/demo/tetris-game` 的时间窗去重思路。
4. `DOUBLE` 在首版全部忽略，不把双击变成隐藏功能。
5. 播放和成功过渡期间锁定普通输入；结果页只有明确的 `OK CLICK` 才重开。

### 6.2 逐状态按键表

| 状态 | UP 短按 | DOWN 短按 | OK 短按 | OK 长按 |
| --- | --- | --- | --- | --- |
| READY | 无状态改变，给 80–120 ms 轻反馈 | 同左 | 开始长度 3 | 返回菜单 |
| PLAYBACK | 忽略 | 忽略 | 忽略 | 中止并返回菜单 |
| INPUT | 记录 `UP` | 记录 `DOWN` | 记录 `OK` | 退出，不追加 token |
| SUCCESS | 忽略 | 忽略 | 忽略 | 返回菜单 |
| RESULT/MAX | 无状态改变 | 无状态改变 | 新会话 | 返回菜单 |

“无状态改变”不是未定义：不移动选中项、不改变成绩、不触发下一轮；可以让机器人轻跳或短暂显示按键标签，确认设备收到了按键，但不要产生会被误解为游戏动作的音效。

### 6.3 误触与长按

实现时应把 `OK` 的长按识别放在输入归约层：长按开始前收到的 `OK PRESS` 若最终升级为 `OK LONG`，不得留下一个不可撤销的 `OK` token。若当前架构只能立即转发 `PRESS`，至少要在 INPUT 状态设置短暂的长按抑制/回滚窗口，并在真机上验证“按住 OK 返回”不会额外推进序列。

## 7. 视觉层级与色彩

| 语义 | 现有 token | 用法 |
| --- | --- | --- |
| 页面背景 | `UI_SKY` | 让主信息集中在面板，不改变品牌天空。 |
| 主文字/边框 | `UI_INK` | 标题、数字、边框、阴影；保证纸白上的高对比。 |
| 普通面板 | `UI_PAPER` | READY、INPUT 的底板。 |
| 选中/当前高亮 | `UI_YELLOW` + 白边 | 当前播放 token、按下反馈；同时保留文字/图形。 |
| 成功 | `UI_GRASS` / `UI_GRASS_DARK` | `GOOD`、完成提示和进度完成态。 |
| 警告 | `UI_ORANGE` | 电量低、等待提示，不表示失败。 |
| 错误 | `UI_RED` | `WRONG`、`TIME UP` 的文字和一次性边框脉冲。 |

视觉顺序固定为：**状态词 > 当前等级/进度 > 三键动作区 > 辅助信息（BEST、电量）**。不要让装饰、吉祥物或电量数字抢过 `WATCH` / `YOUR TURN`。

三枚键的色彩可以分别使用天空深蓝、橙、黄作为区分，但每一枚都必须同时有 `UP`/`DOWN`/`OK` 文本与 `↑`/`↓`/`●` 符号。错误不能只用红色，成功不能只用绿色；都要有明确英文词和声音/节奏替代。

## 8. 动效与音效

### 8.1 动效时间基线

| 事件 | 默认表现 | 设计目的 |
| --- | --- | --- |
| 开始 | `READY` 静止 500 ms，随后首个 token 高亮 | 给用户准备时间，不突然闪屏。 |
| 播放一个 token | 标准：高亮 360 ms、熄灭/间隔 160 ms；设置页可选慢/标准/快 | 分隔提示，但不改变生成的序列。 |
| 用户按键 | 对应卡片反色/白边 180–220 ms，进度点填充 | 让没有声音的用户也知道输入已收录。 |
| 成功 | 面板绿闪一次（约 180 ms）+ 吉祥物现有 110/140 ms jump，停留总计约 900 ms | 奖励明确但不刺眼。 |
| 错误/超时 | 面板红边单次脉冲约 220 ms，随后静止结果页 | 不使用高频闪烁；错误原因靠文字表达。 |

动画必须可在低帧率或局部刷新失败时退化为静态颜色和文字；不要依赖连续全屏重绘。眨眼沿用现有吉祥物节奏，不叠加多条无限循环动画。

### 8.2 音调建议

音频只是第二通道，视觉高亮才是权威提示。建议先用中频、短方波或简单 PCM 音符，实际频率和音量上板校准：

| token/事件 | 建议音高 | 时长 |
| --- | ---: | ---: |
| `UP` | 523 Hz 左右 | 180–220 ms |
| `DOWN` | 659 Hz 左右 | 180–220 ms |
| `OK` | 784 Hz 左右 | 180–220 ms |
| `GOOD` | 523 → 659 → 784 Hz | 每音 90–120 ms |
| `WRONG` | 220 Hz 左右低音 | 220–300 ms |
| `TIME UP` | 两个下降音 | 总计 300–400 ms |
| `MAX CLEAR` | 三音上行后长音 | 总计不超过 700 ms |

播放任务从事件队列取音，按键回调和 LVGL 回调只投递事件。不要在 NVS 写入期间同时强行启动长 PCM；新纪录保存应发生在结果页或音频事件边界。音频初始化/写入失败时，在 READY/RESULT 顶栏显示小型 `SOUND OFF` 图标或文字一次，后续不反复报错。

## 9. 错误、降级与恢复

| 故障 | 用户看到什么 | 行为边界 |
| --- | --- | --- |
| 显示/LVGL 初始化失败 | 无玩法页 | 属于系统硬依赖，按现有主流程记录日志并停止，不在本页伪造文本界面。 |
| 按键初始化失败 | 主菜单入口标 `[FAIL]`，不可进入 | 不尝试在玩法内另建 ADC unit。 |
| ES8311 不可用/播放失败 | 视觉序列照常；`SOUND OFF` | 不降低序列规则，不把声音缺失判为答错。 |
| CW2017 不可用 | 隐藏电量图标/百分比 | 不阻塞训练。SOC `<20%` 时若可读，只做橙/红色提醒，不强制退出。 |
| NVS 初始化/读取失败 | `BEST --` 或 `SAVE OFF`；本次成绩仍显示 | 不擦除无关 NVS；成绩仅保留在 RAM，重启后可丢失。 |
| NVS 写入失败 | RESULT 上短暂显示 `NOT SAVED` | 不回滚本次已完成成绩；记录一次日志，避免每帧重试。 |
| 输入队列满/事件重复 | 不推进额外 token | 丢弃重复或过期事件并记录受控日志；用户可在结果页重新开始。 |
| 低电量 | 右上角提醒 | 不在一局中强制休眠；遵循系统已有电源策略。 |

所有失败提示都要给出可理解的下一步（继续看、重新开始或长按返回），不显示错误码作为唯一信息。结果页保持可操作，不用自动跳转掩盖失败。

## 10. 老人友好与无障碍

- **不靠颜色单独传达**：每个状态都有大号 `WATCH`、`YOUR TURN`、`GOOD`、`WRONG`、`TIME UP` 词；按键有文字和形状符号。
- **稳定、可预测**：同一位置持续显示状态词和三键图例；不滚动、不让信息突然换位；`OK START`、`TRY AGAIN`、`HOLD OK BACK` 明确写在屏上。
- **足够反应时间**：单个预期 token 默认 5 秒超时；先测试标准 360/160 ms 及慢/快设置的真机可读性，只调整节奏常量，不改变随机序列规则。
- **听觉替代视觉**：音频关闭、听力受限或扬声器故障时，亮起时长、进度点和文字仍完整；不要用“无声模式”删掉关键反馈。
- **视觉替代听觉**：音调只做提示；三个 token 使用不同的高亮位置、文字、符号，不能只靠音高记忆。
- **避免闪烁风险**：错误和成功最多一次短脉冲，不使用 3 Hz 以上反复闪烁；动画失效时保留静态结果。
- **降低误触成本**：不使用双击功能；结果页不会因 UP/DOWN 误触重开；长按 OK 的返回语义始终一致。
- **字体与对比**：首版沿用已有 Montserrat 14/20 和高对比 `UI_INK`/`UI_PAPER`；若产品必须显示中文，后续只加入所需字形子集并重新检查内部 RAM、最大连续堆和刷新性能。
- **健康边界**：文案使用“训练”“本轮”“最高完成长度”，不使用“提升记忆力”“认知诊断”等医疗或效果承诺。

## 11. NVS 与实现交接约束

### 11.1 最小数据模型

```text
namespace: memory
key:       best_level   uint8 (0..12)
optional:  schema       uint8
```

首次读取不到 key 时按 `best_level=0` 处理。写入只在 RESULT/MAX RESULT 且 `clear_level > best_level` 时请求一次；不要在播放每个 token、每次按键或 LVGL tick 中写 Flash。沿用番茄钟分支的异步保存思路，但不为一个字节引入完整会话恢复。

### 11.2 与当前工程的边界

- 页面、状态机、计时、动画和序列模型归 `main`；不要为本玩法扩展 `components/bsp`。
- 按键回调只入现有输入队列；非 LVGL 任务更新控件前取得 `bsp_lvgl_lock()`。
- 音频和 NVS 都放工作任务；页面退出前先停止 timer/task，再删除 screen 和对象指针。
- 预计实现文件为 `main/demo_memory.c` 加一个不依赖 LVGL/ESP-IDF 的小型 `memory_model`；按现有 `demo.h`、`main/CMakeLists.txt`、`main.c` 注册。
- `main/main.c` 负责开机页、主菜单、设置页、状态信息和退出页。
- 由于现有 `ui_pixel_screen_create()` 标题和面板已提供品牌结构，不新建第二套主题或通用页面工厂。

## 12. 首版范围（MVP）

### 必须交付

- 开机界面、包含 `MEMORY`、`SETTINGS`、`EXIT` 的主界面，以及覆盖 READY、PLAYBACK、INPUT、SUCCESS、RESULT/MAX 的记忆 screen。
- 三值序列，长度 3 起步；每轮答对后重新生成下一长度的完整序列，最大 12；相邻 token 可以重复。
- 视觉高亮 + 三个可区分音调；音频失败时视觉完整降级。
- 运行时亮度、声音、慢/标准/快节奏设置；主外壳持续显示时间和电量。
- `PRESS`/`CLICK` 去重、5 秒单步超时、答错立即结束、`OK LONG` 返回。
- `BEST` 在 NVS 持久化；NVS 失败不阻止本次训练，并明确 `SAVE OFF`/`NOT SAVED`。
- 右上角可缺省电量、低电量提醒和既有 `ui_pixel` 视觉身份。
- 纯模型 host 测试：完整随机重生成、正确/错误、超时、上限 12、成绩更新和存储边界。

### 明确不做

- 暂停、用户档案、每日任务、联网同步、排行榜；设置持久化和手动校时也后置。
- 回放正确答案、逐键复盘、语音输入、触摸、震动或新增硬件接口。
- 完整中文字体、复杂像素插画、连续背景音乐、每帧统计上传。
- 医疗、教育效果或认知能力结论。

## 13. 验收清单

### Host 逻辑验收

1. 长度 3 的初始序列可完整复现；每次成功都重新生成下一长度的完整序列且不继承上一轮前缀，长度 12 后不再生成新序列。
2. 错误 token 立即转 RESULT；未输入满 5 秒转 `TIME UP`；正确完成才更新 `clear_level`。
3. `best_level` 只取完整通过的最大长度，0/12 边界正确；NVS 读不到、读坏、写失败均有降级结果。
4. `PRESS + CLICK` 同一动作只计一次；`DOUBLE` 不改变模型；`OK LONG` 不留下 token。

### 真机验收

1. 在 240 × 320 竖屏上确认开机页、主菜单、设置行、标题、云朵、时间、电量、面板、三键卡片、进度点无重叠；局部刷新不撕裂。
2. 分别按住三键确认 ADC 窗口和短按/长按边界；反复快速输入不丢位、不重复计数。
3. 在安静环境和听力受限场景确认三音可区分；拔除/禁用音频后视觉流程仍可完成。
4. 连续完成新纪录、断电重启后确认 `BEST` 保留；模拟 NVS 错误时确认不擦除其他数据。
5. 低电量和电量计不可用时确认提醒/隐藏逻辑；检查内部 RAM、最大连续堆和长会话稳定性。

## 14. 后续扩展顺序

1. **低风险体验**：暂停后继续、重新播放上一轮、显式“清除最高成绩”、设置持久化；均应保持三键单一动作模型。
2. **本地化**：按需加入中文短词字形子集或位图字库，先做 RAM/刷新预算，再替换 ASCII 标签。
3. **陪伴玩法**：每日目标、连续完成记录、更多视觉主题；不能把统计包装成健康结论。
4. **连接能力**：BLE 同步成绩或多人对战，另行设计隐私、配对、功耗和离线回退；不把联网前置到 MVP。

首版的成功标准是“用户无需说明书即可完成一局，并能看懂为什么结束、最高成绩是多少”。任何扩展都不能牺牲这一条。
