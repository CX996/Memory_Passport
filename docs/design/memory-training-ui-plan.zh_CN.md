# “记忆通行证”界面设计方案

> 文档类型：独立 UI 设计方案
> 适用产品：FoloToy AI Passport  规范对应页：[English](memory-training-ui-plan.md)
> 目标版本：离线 MVP  评审状态：已实现基线

## 1. 设计结论

“记忆通行证”是一个聚焦的产品外壳，包含开机界面、标准游戏主菜单和一个顺序记忆玩法。主菜单固定按“开始游戏、选择难度、基础设置、更多功能、退出”五项纵向等距排列；用户进入游戏后先看并听设备播放的“上 / 下 / 确定”序列，再按同样顺序复现。初始序列长度由难度决定（轻松 2、标准 3、挑战 4，默认标准），每完整答对一轮都重新生成一串长度增加一项、且不继承上一轮内容的随机序列，最多到 12；答错或单步超时结束。最高成绩是本地保存的“完整复现过的最高序列长度”，不是联网排名，也不是医疗或认知能力评估。

首版画面全部复用 `ui_pixel` 的天空、草地、通栏纸色状态栏、整页纸色描边面板和电视机器人。开机页和全部产品页面的用户可见文案使用简体中文；内部状态名和事件名仍可使用英文标识符。固件落地时只打包本界面实际使用的中文字形，不引入完整通用 CJK 字库，并重新检查内部 RAM、最大连续堆和刷新性能。

## 2. 已确认的约束与假设

| 项目 | 设计约束 |
| --- | --- |
| 显示 | ST7789P3 240 × 320，竖屏 RGB565；布局使用固定像素和局部刷新，不依赖触摸或 MISO。 |
| 内存 | ESP32-C3 无 PSRAM；不创建整屏双缓冲、不缓存整段 PCM。序列最多 12 个三值 token，可用小型静态数组。 |
| 输入 | GPIO0 ADC 电阻梯产生 `UP`、`DOWN`、`OK`；逻辑输入优先消费 `PRESS`，仅在驱动不提供 `PRESS` 时回退到 `CLICK`。 |
| 全局导航 | 菜单中 `UP/DOWN CLICK` 在五项入口间移动，`OK CLICK` 进入；屏上对应显示“上 / 下 / 确定”。功能页 `OK LONG` 由全局路由拦截并返回菜单。 |
| 音频 | ES8311 播放为阻塞 API，必须由音频工作任务消费事件；音频不可用时玩法仍可完整进行。 |
| 电池 | CW2017 是可缺省能力；有读数时显示百分比，读数为 `-1` 时在状态栏显示 `--%`，不伪造电量。 |
| 持久化 | 使用现有 NVS 分区，不新增分区；只保存 `best_level`（0–12）及必要的版本信息。 |
| 难度 | 提供“轻松 / 标准 / 挑战”三档：起始长度分别为 2 / 3 / 4，单步输入时间分别为 7 / 5 / 4 秒，每项提示节奏分别为 580 / 460 / 360 ms；默认“标准”。 |
| 随机序列 | 每局按当前难度生成完整初始序列；每完整答对一轮都为下一长度重新生成完整随机序列，不继承上一轮顺序或前缀。token 独立抽取，相邻重复属于有效随机结果。随机种子不持久化。 |
| 产品外壳 | 开机界面后进入标准游戏主菜单，五项入口依次为“开始游戏、选择难度、基础设置、更多功能、退出”；整体居中、纵向等距排列。“基础设置”只提供屏幕亮度和游戏音效。“更多功能”包含“玩法说明、最高记录、版本信息”，不提供硬件测试入口。 |
| 状态信息 | 不显示或模拟墙上时间；状态栏左侧留空，页面标题严格居中，右侧仅显示电量。电量计可读时显示百分比，不可用时显示 `--%`。 |
| 计分口径 | `level` 是正在挑战的序列长度；`clear_level` 是完整复现的最后长度；`best_level = max(best_level, clear_level)`。 |
| 目标人群 | 普通成人为默认节奏，兼顾老人易读、易听、易恢复；不做医疗宣称，不把成绩解释为健康指标。 |

## 3. 信息架构

```text
开机界面
  └─ 主菜单：开始游戏 / 选择难度 / 基础设置 / 更多功能 / 退出
      ├─ 开始游戏 → READY（准备）
      │   └─ 确定短按 → PLAYBACK（设备播放序列）
      │       └─ 播放完 → INPUT（用户复现）
      │           ├─ 全部正确 → SUCCESS → 重新随机生成下一长度 → PLAYBACK
      │           ├─ 答错 → RESULT（错误）
      │           └─ 超过当前难度的单步时间仍无输入 → RESULT（超时）
      │       └─ 长按确定（任意游戏状态）→ 返回主菜单
      │   └─ 成功完成长度 12 → MAX RESULT（全部完成）
      ├─ 选择难度（轻松 / 标准 / 挑战）
      ├─ 基础设置（屏幕亮度 / 游戏音效）
      ├─ 更多功能（玩法说明 / 最高记录 / 版本信息）
      └─ 退出（安全关机提示）
```

“最高记录”常驻准备页和结果页，并可从“更多功能”查看。“选择难度”显示并确认“轻松 / 标准 / 挑战”；“基础设置”只保留屏幕亮度和游戏音效；“更多功能”只提供玩法说明、最高记录和版本信息，不提供硬件测试、用户档案或联网流程。

## 4. 页面与状态

产品外壳页共用中文文案、仅显示电量的状态栏、整页纸色描边面板和三键导航：

| 页面 | 必须显示 |
| --- | --- |
| 开机页 | 产品标识与简短启动提示，完成后自动进入主菜单。 |
| 主菜单 | 居中、纵向等距排列“开始游戏、选择难度、基础设置、更多功能、退出”；上/下移动，确定进入。 |
| 选择难度 | “轻松 / 标准 / 挑战”及当前选择；同时显示对应的起始长度、单步时间和提示节奏。 |
| 基础设置 | 只显示“屏幕亮度、游戏音效”。 |
| 更多功能 | 只显示“玩法说明、最高记录、版本信息”，不显示硬件测试入口。 |
| 退出页 | 中文退出确认/安全关机提示，并提供返回主菜单的三键路径。 |

玩法只有一个 screen，状态机决定同一套控件的文案、颜色和可用输入。状态切换由纯逻辑模型决定，LVGL 只负责呈现。

| 状态 | 屏幕重点 | 进入/离开 | 按键与计时 |
| --- | --- | --- | --- |
| `READY` 准备 | “记忆训练”“最高记录 n”、三枚按键图例、“按确定开始”“长按确定返回” | 进入页面、重试前、结果停留后 | `OK CLICK` 按当前难度开始；`UP/DOWN CLICK` 不改变设置，只做机器人三键反馈；`OK LONG` 返回。停留不超时。 |
| `PLAYBACK` 播放 | “第 n 关”“请记住”、当前 token 高亮、`i/n` 进度 | READY 开始或 SUCCESS 后自动进入 | 忽略普通按键，避免用户抢答；`OK LONG` 仍可退出。每项提示使用当前难度的 580 / 460 / 360 ms 节奏。 |
| `INPUT` 复现 | “第 n 关”“请复现”、`i/n`、三个大按键卡片、进度点 | 播放完成后立即进入 | 每个预期 token 使用当前难度的 7 / 5 / 4 秒时限；正确按键立即反馈并进入下一格；错误立即结束；`OK LONG` 返回；`DOUBLE` 不产生额外输入。 |
| `SUCCESS` 本轮通过 | “完成”“通过 n”、短暂全屏/面板绿闪、机器人跳一下 | INPUT 全部正确 | 锁定输入约 900 ms；`n < 12` 为下一长度重新生成完整随机序列并进入 PLAYBACK；`n = 12` 进入 MAX RESULT。 |
| `RESULT` 结束 | “错误”或“超时”“已通过 n”“最高记录 n”“再试一次”“长按确定返回” | 错误、超时或最高等级完成 | `OK CLICK` 开始新会话（先显示 500 ms 准备提示，再按当前难度播放初始序列）；`UP/DOWN CLICK` 不改变成绩；`OK LONG` 返回。结果不自动消失。 |
| `MAX RESULT` | “全部完成”“12/12”“最高记录 12” | 完整通过长度 12 | 与 RESULT 相同；不生成长度 13。 |

### 4.1 成绩显示的明确口径

- 首轮长度由难度决定（轻松 2、标准 3、挑战 4）；若在首轮出错，显示“已通过 0”和对应的“失败于 n”，不会把未完成的首轮长度记为最高记录。
- 例如标准难度完成长度 3 后在长度 4 出错，显示“已通过 3”“失败于 4”。
- 每轮成功先更新 RAM 中的 `clear_level`；只在会话结束且产生新纪录时请求 NVS 写入。
- “最高记录 12”表示已完整复现长度 12，达到首版上限；不显示百分比或“智力等级”。

## 5. 240 × 320 布局草案

坐标是设计基线而非必须逐像素照抄；控件尺寸应保持稳定，便于单 DMA 局部刷新。

```text
 y=0   ┌──────────────────────── 240 ────────────────────────┐
       │  [留空]            [记忆训练]            [电量]     │  0–25
 y=32  │  ┌───────── 整页纸色描边面板 ────────────────┐  │
       │  │ 第 4 关                  最高记录 7           │  │  56–80
       │  │                 请记住 / 请复现                │  │  84–112
       │  │                    ● ● ○ ○                    │  │  120–144
       │  │                  长按确定返回                  │  │  154–174
       │  └──────────────────────────────────────────────┘  │
 y=194 │       [机器人沿三个按键方块横向移动并跳起]          │
 y=244 │    ┌──────┐       ┌──────┐       ┌──────┐          │
       │    │  上  │       │  下  │       │ 确定 │          │  244–284
       │    └──────┘       └──────┘       └──────┘          │
 y=286 │  草地底栏（沿用 ui_pixel_screen_create）            │
 y=320 └──────────────────────────────────────────────────────┘
```

- 外壳：复用 `ui_pixel_screen_create()` 的云朵和草地。顶部使用通栏纸色状态栏，左侧留空、页面标题严格居中、右侧显示电量，不显示时间。
- 页面面板沿用 `ui_pixel_panel_create()` 的 4 px 墨边、右下硬阴影和内边距；外壳页使用 `x=8,y=32,w=224,h=275`，游戏页使用 `x=8,y=32,w=224,h=204`，为机器人和三键区域留出空间；不要把面板再嵌套成卡片套卡片。
- 三枚按键方块在底部等宽、等距排列，分别显示“上”“下”“确定”和对应符号；机器人在方块上方共用一条水平移动轨道。
- 进度点只表示已输入数量，不显示 token 内容，防止无意中泄露答案；最多 12 个点分两行或缩成 8 px 方块。
- 吉祥物沿用 `ui_pixel_mascot_create()`；收到有效的“上 / 下 / 确定”短按后，先移动到对应方块，再跳起一次确认该按键。动画不得改变输入判定，也不得因 `PRESS + CLICK` 重复播放。
- 固定状态栏只显示电量；左侧空位与右侧电量列平衡，使标题保持居中。不可覆盖云朵，也不要把电量作为训练主信息。

### 5.1 各状态的内容差异

| 区域 | READY | PLAYBACK | INPUT | RESULT |
| --- | --- | --- | --- | --- |
| 面板顶部 | “最高记录 n” | “第 n 关” + “请记住” | “第 n 关” + “请复现” | “已通过 n” + “最高记录 n” |
| 中央 | 静态三键图例 | 只有当前 token 方块高亮 | 按下的方块短暂高亮 | 原因词（“错误”/“超时”） |
| 底栏 | “按确定开始” | `i/n` | `i/n` + 进度点 | “再试一次” |
| 吉祥物 | 有效短按时移动到对应方块并跳起 | 普通输入锁定 | 每次有效输入移动到对应方块并跳起 | 确定重试时移动并跳起一次 |

## 6. 三键交互规范

### 6.1 事件优先级

1. `OK LONG` 是全局返回，优先级高于玩法动作。
2. 训练输入只认一个“逻辑按下”：优先 `PRESS`，或在没有 `PRESS` 的驱动版本中使用 `CLICK`。
3. 同一物理动作产生的 `PRESS + CLICK` 不得计为两个 token；可沿用 `origin/demo/tetris-game` 的时间窗去重思路。
4. `DOUBLE` 在首版全部忽略，不把双击变成隐藏功能。
5. 播放和成功过渡期间锁定普通输入；结果页只有明确的 `OK CLICK` 才重开。

### 6.2 逐状态按键表

| 状态 | “上”短按 | “下”短按 | “确定”短按 | “确定”长按 |
| --- | --- | --- | --- | --- |
| READY | 无状态改变，机器人移动并跳起 | 同左 | 机器人确认后按当前难度开始 | 返回菜单 |
| PLAYBACK | 忽略 | 忽略 | 忽略 | 中止并返回菜单 |
| INPUT | 记录 `UP`，机器人移动并跳起 | 记录 `DOWN`，机器人移动并跳起 | 记录 `OK`，机器人移动并跳起 | 退出，不追加 token |
| SUCCESS | 忽略 | 忽略 | 忽略 | 返回菜单 |
| RESULT/MAX | 无状态改变，机器人移动并跳起 | 同左 | 机器人确认后开始新会话 | 返回菜单 |

“无状态改变”不是未定义：不移动选中项、不改变成绩、不触发下一轮。每个被接收的短按只触发一次“移动到对应方块 → 跳起 → 落回”的机器人反馈；被锁定、重复或升级为长按的事件不触发确认动画。

### 6.3 误触与长按

实现时应把 `OK` 的长按识别放在输入归约层：长按开始前收到的 `OK PRESS` 若最终升级为 `OK LONG`，不得留下一个不可撤销的 `OK` token。若当前架构只能立即转发 `PRESS`，至少要在 INPUT 状态设置短暂的长按抑制/回滚窗口，并在真机上验证“按住 OK 返回”不会额外推进序列。

## 7. 视觉层级与色彩

| 语义 | 现有 token | 用法 |
| --- | --- | --- |
| 页面背景 | `UI_SKY` | 让主信息集中在面板，不改变品牌天空。 |
| 主文字/边框 | `UI_INK` | 标题、数字、边框、阴影；保证纸白上的高对比。 |
| 普通面板 | `UI_PAPER` | READY、INPUT 的底板。 |
| 选中/当前高亮 | `UI_YELLOW` + 白边 | 当前播放 token、按下反馈；同时保留文字/图形。 |
| 成功 | `UI_GRASS` / `UI_GRASS_DARK` | “完成”、通过提示和进度完成态。 |
| 警告 | `UI_ORANGE` | 电量低、等待提示，不表示失败。 |
| 错误 | `UI_RED` | “错误”“超时”的文字和一次性边框脉冲。 |

视觉顺序固定为：**状态词 > 当前等级/进度 > 三键动作区 > 辅助信息（最高记录、电量）**。不要让装饰、吉祥物或电量数字抢过“请记住 / 请复现”。

三枚键的色彩可以分别使用天空深蓝、橙、黄作为区分，但每一枚都必须同时有“上 / 下 / 确定”文本与 `↑`/`↓`/`●` 符号。错误不能只用红色，成功不能只用绿色；都要有明确中文词和声音/节奏替代。

## 8. 动效与音效

### 8.1 动效时间基线

| 事件 | 默认表现 | 设计目的 |
| --- | --- | --- |
| 开始 | `READY` 静止 500 ms，随后首个 token 高亮 | 给用户准备时间，不突然闪屏。 |
| 播放一个 token | 轻松 / 标准 / 挑战的每项提示节奏为 580 / 460 / 360 ms | 难度改变节奏，但不改变每轮独立随机规则。 |
| 用户按键 | 对应方块反色/白边；机器人移到该方块并跳起一次；进度点填充 | 让实体键与视觉反馈一一对应。 |
| 成功 | 面板绿闪一次（约 180 ms）+ 吉祥物现有 110/140 ms jump，停留总计约 900 ms | 奖励明确但不刺眼。 |
| 错误/超时 | 面板红边单次脉冲约 220 ms，随后静止结果页 | 不使用高频闪烁；错误原因靠文字表达。 |

动画必须可在低帧率或局部刷新失败时退化为静态颜色和文字；不要依赖连续全屏重绘。眨眼沿用现有吉祥物节奏，不叠加多条无限循环动画。

### 8.2 音调建议

音频只是第二通道，视觉高亮才是权威提示。建议先用中频、短方波或简单 PCM 音符，实际频率和音量上板校准：

| token/事件 | 建议音高 | 时长 |
| --- | ---: | ---: |
| `UP` | 523 Hz 左右 | 180–220 ms |
| `DOWN` | 659 Hz 左右 | 180–220 ms |
| `OK` | 784 Hz 左右 | 180–220 ms |
| `GOOD` | 523 → 659 → 784 Hz | 每音 90–120 ms |
| `WRONG` | 220 Hz 左右低音 | 220–300 ms |
| `TIME UP` | 两个下降音 | 总计 300–400 ms |
| `MAX CLEAR` | 三音上行后长音 | 总计不超过 700 ms |

播放任务从事件队列取音，按键回调和 LVGL 回调只投递事件。不要在 NVS 写入期间同时强行启动长 PCM；新纪录保存应发生在结果页或音频事件边界。音频初始化/写入失败时，在准备页/结果页顶栏显示小型“声音不可用”提示一次，后续不反复报错。

## 9. 错误、降级与恢复

| 故障 | 用户看到什么 | 行为边界 |
| --- | --- | --- |
| 显示/LVGL 初始化失败 | 无玩法页 | 属于系统硬依赖，按现有主流程记录日志并停止，不在本页伪造文本界面。 |
| 按键初始化失败 | 主菜单入口标“按键不可用”，不可进入 | 不尝试在玩法内另建 ADC unit。 |
| ES8311 不可用/播放失败 | 视觉序列照常；“声音不可用” | 不降低序列规则，不把声音缺失判为答错。 |
| CW2017 不可用 | 状态栏电量显示 `--%` | 不阻塞训练。SOC `<20%` 时若可读，只做橙/红色提醒，不强制退出。 |
| NVS 初始化/读取失败 | “最高记录 --”或“无法保存”；本次成绩仍显示 | 不擦除无关 NVS；成绩仅保留在 RAM，重启后可丢失。 |
| NVS 写入失败 | 结果页短暂显示“未保存” | 不回滚本次已完成成绩；记录一次日志，避免每帧重试。 |
| 输入队列满/事件重复 | 不推进额外 token | 丢弃重复或过期事件并记录受控日志；用户可在结果页重新开始。 |
| 低电量 | 右上角提醒 | 不在一局中强制休眠；遵循系统已有电源策略。 |

所有失败提示都要给出可理解的下一步（继续看、重新开始或长按返回），不显示错误码作为唯一信息。结果页保持可操作，不用自动跳转掩盖失败。

## 10. 老人友好与无障碍

- **不靠颜色单独传达**：每个状态都有大号“请记住”“请复现”“完成”“错误”“超时”词；按键有中文文字和形状符号。
- **稳定、可预测**：同一位置持续显示状态词和三键图例；不滚动、不让信息突然换位；“按确定开始”“再试一次”“长按确定返回”明确写在屏上。
- **足够反应时间**：轻松 / 标准 / 挑战的单步时限分别为 7 / 5 / 4 秒，提示节奏分别为 580 / 460 / 360 ms；真机只校准这些参数，不改变每轮独立随机规则。
- **听觉替代视觉**：音频关闭、听力受限或扬声器故障时，亮起时长、进度点和文字仍完整；不要用“无声模式”删掉关键反馈。
- **视觉替代听觉**：音调只做提示；三个 token 使用不同的高亮位置、文字、符号，不能只靠音高记忆。
- **避免闪烁风险**：错误和成功最多一次短脉冲，不使用 3 Hz 以上反复闪烁；动画失效时保留静态结果。
- **降低误触成本**：不使用双击功能；结果页不会因 UP/DOWN 误触重开；长按 OK 的返回语义始终一致。
- **字体与对比**：首版沿用高对比 `UI_INK`/`UI_PAPER`，并只加入本界面实际需要的中文字形子集；重新检查内部 RAM、最大连续堆和刷新性能。
- **健康边界**：文案使用“训练”“本轮”“最高完成长度”，不使用“提升记忆力”“认知诊断”等医疗或效果承诺。

## 11. NVS 与实现交接约束

### 11.1 最小数据模型

```text
namespace: memory
key:       best_level   uint8 (0..12)
optional:  schema       uint8
```

首次读取不到 key 时按 `best_level=0` 处理。写入只在 RESULT/MAX RESULT 且 `clear_level > best_level` 时请求一次；不要在播放每个 token、每次按键或 LVGL tick 中写 Flash。沿用番茄钟分支的异步保存思路，但不为一个字节引入完整会话恢复。

### 11.2 与当前工程的边界

- 页面、状态机、计时、动画和序列模型归 `main`；不要为本玩法扩展 `components/bsp`。
- 按键回调只入现有输入队列；非 LVGL 任务更新控件前取得 `bsp_lvgl_lock()`。
- 音频和 NVS 都放工作任务；页面退出前先停止 timer/task，再删除 screen 和对象指针。
- 预计实现文件为 `main/demo_memory.c` 加一个不依赖 LVGL/ESP-IDF 的小型 `memory_model`；按现有 `demo.h`、`main/CMakeLists.txt`、`main.c` 注册。
- `main/main.c` 负责开机页、五项主菜单、难度页、基础设置、更多功能、状态信息和退出页。
- 由于现有 `ui_pixel_screen_create()` 和 `ui_pixel_panel_create()` 已提供状态栏与整页描边面板结构，不新建第二套主题或通用页面工厂。

## 12. 首版范围（MVP）

### 必须交付

- 全中文开机界面、依次包含“开始游戏、选择难度、基础设置、更多功能、退出”的五项主菜单，以及覆盖 READY、PLAYBACK、INPUT、SUCCESS、RESULT/MAX 的记忆 screen。
- “轻松 / 标准 / 挑战”三档分别从长度 2 / 3 / 4 起步，单步时限为 7 / 5 / 4 秒，提示节奏为 580 / 460 / 360 ms。
- 三值序列每完整答对一轮都重新生成下一长度的完整随机序列，最大 12；不继承上一轮内容，相邻 token 可以重复。
- 视觉高亮 + 三个可区分音调；音频失败时视觉完整降级。
- “基础设置”只含屏幕亮度和游戏音效；“更多功能”只含玩法说明、最高记录和版本信息；主外壳保持标题居中、右侧显示电量，不显示时间。
- 游戏底部机器人按实体“上 / 下 / 确定”短按移动到对应方块并跳起；`PRESS`/`CLICK` 去重、按难度计时、答错立即结束、`OK LONG` 返回。
- “最高记录”在 NVS 持久化；NVS 失败不阻止本次训练，并明确显示“无法保存”或“未保存”。
- 状态栏持续保留电量位置；不可用时显示 `--%`，并保留低电量提醒和既有 `ui_pixel` 视觉身份。
- 纯模型 host 测试：完整随机重生成、正确/错误、超时、上限 12、成绩更新和存储边界。

### 明确不做

- 暂停、用户档案、每日任务、联网同步、排行榜；设置持久化及墙上时间的显示或校时不在首版范围内。
- 回放正确答案、逐键复盘、语音输入、触摸、震动或新增硬件接口。
- 覆盖全部 CJK 的通用字体、复杂像素插画、连续背景音乐、每帧统计上传。
- 医疗、教育效果或认知能力结论。

## 13. 验收清单

### Host 逻辑验收

1. 三档分别从长度 2 / 3 / 4 开始；每次成功都重新生成下一长度的完整序列且不继承上一轮前缀，长度 12 后不再生成新序列。
2. 错误 token 立即转 RESULT；超过当前难度的 7 / 5 / 4 秒仍未输入则转超时结果；正确完成才更新 `clear_level`。
3. `best_level` 只取完整通过的最大长度，0/12 边界正确；NVS 读不到、读坏、写失败均有降级结果。
4. `PRESS + CLICK` 同一动作只计一次；`DOUBLE` 不改变模型；`OK LONG` 不留下 token。

### 真机验收

1. 在 240 × 320 竖屏上确认“左侧留空 / 标题居中 / 右侧电量”的状态栏和整页纸色描边面板符合定稿；全中文开机页、五项主菜单、难度页、基础设置、更多功能、退出页、三键方块和进度点无重叠，局部刷新不撕裂。
2. 分别按住三键确认 ADC 窗口和短按/长按边界；每个有效短按只让机器人移动到对应方块并跳起一次，反复快速输入不丢位、不重复计数或动画。
3. 在安静环境和听力受限场景确认三音可区分；拔除/禁用音频后视觉流程仍可完成。
4. 连续完成新纪录、断电重启后确认“最高记录”保留；模拟 NVS 错误时确认不擦除其他数据。
5. 低电量时确认提醒，电量计不可用时确认状态栏显示 `--%`；检查内部 RAM、最大连续堆和长会话稳定性。

## 14. 后续扩展顺序

1. **低风险体验**：暂停后继续、重新播放上一轮、显式“清除最高成绩”、设置持久化；均应保持三键单一动作模型。
2. **其他语言**：中文是首版基线；后续语言复用同一布局，并重新检查字形、RAM 和刷新预算。
3. **陪伴玩法**：每日目标、连续完成记录、更多视觉主题；不能把统计包装成健康结论。
4. **连接能力**：BLE 同步成绩或多人对战，另行设计隐私、配对、功耗和离线回退；不把联网前置到 MVP。

首版的成功标准是“用户无需说明书即可完成一局，并能看懂为什么结束、最高成绩是多少”。任何扩展都不能牺牲这一条。
