# “记忆通行证”功能设计方案

> 文档类型：产品功能设计基线
> 目标平台：FoloToy AI Passport（ESP32-C3，240 × 320，三键，ES8311）
> 目标版本：离线 MVP  评审状态：实现基线

## 1. 产品定位

“记忆通行证”是一款短时、离线的顺序记忆训练工具。设备先播放一串按键提示，用户再用
三个实体按键按相同顺序复现；每完整答对一轮，就重新生成一串长度增加一项的随机序列，直到
出错或达到上限。

它的产品价值是让用户随时完成一局简单的认知训练，而不是给用户做医学测评。所有成绩只
用于描述本机训练表现，不推导“记忆力提升”、健康状况或认知能力结论。

默认按“普通成人可玩、老人也能看懂和听清”设计。儿童专版、老人专版可以在同一模型上
调整节奏和文案，不在首版拆成两套产品。

## 2. 目标与非目标

### 2.1 首版目标

- 用户不看说明书也能在 1 分钟内开始一局。
- 一局通常持续 30 秒至 3 分钟，失败后能立即重来。
- 视觉和听觉都能完成训练；音频故障或关闭时仍可完整游玩。
- 最高完整复现长度在重启后保留。
- 玩法逻辑可在没有 ESP-IDF 和真实硬件的主机测试中验证。
- 产品外壳包含开机界面、聚焦的主界面、简洁设置页和退出页；主界面持续显示时间与电量。

### 2.2 首版不做

- 本地或云端大模型、联网账号、排行榜和跨设备同步。
- 医疗诊断、能力评级、训练效果承诺。
- 复杂的每日 streak、日历统计或社交系统；当前没有可靠的绝对时间来源。
- 大量图片、GIF、长录音或连续背景音乐。
- 触摸、震动、NFC 交互和新的板级接口。

## 3. 核心用户流程

```text
主菜单
  → MEMORY 准备页（也可进入设置/退出）
  → 设备播放序列
  → 用户按键复现
       ├─ 全部正确 → 成功反馈 → 重新生成更长的随机序列 → 再次播放
       └─ 答错/超时 → 结果页 → 重试或返回
```

用户每局只需要理解两个动作：**看/听提示**，然后**按同样顺序复现**。训练中不要求用户
输入文字、选择复杂设置或连接手机。

## 4. MVP 玩法规则

### 4.1 序列

- 三个 token 分别对应 `UP`、`DOWN`、`OK`。
- 每局从长度 3 开始。
- 完整复现当前序列后，按下一长度重新生成完整随机序列；不继承上一轮的顺序或前缀。
- 首版上限为长度 12；完整通过 12 后进入结算，不生成第 13 项。
- 序列使用本局伪随机数生成；每个 token 独立抽取，相邻 token 可以重复，这是有效随机结果。
- 随机种子只在本次运行中使用，不保存到 NVS；重启后允许产生不同序列。

### 4.2 设备提示

- 设备按序列逐项高亮对应按键，并播放对应短音调。
- 标准节奏为高亮约 360 ms、间隔约 160 ms；设置页提供慢/标准/快三档。真实硬件上只校准
  这些节奏参数，不改变随机规则。
- 播放阶段禁止普通输入，避免用户抢答；`OK` 长按仍可退出。
- 播放结束后立即进入用户输入阶段，并明确提示 `YOUR TURN`。

### 4.3 用户复现

- 输入阶段每次只接受一个逻辑按下事件，顺序必须与序列完全一致。
- `PRESS` 是首选事件；若底层版本没有可靠的 `PRESS`，才回退到 `CLICK`。
- 同一物理按键可能同时产生 `PRESS` 与 `CLICK`，必须去重，不能计为两个 token。
- 每个待输入 token 默认有 5 秒；超时等同于本轮失败，原因显示为 `TIME UP`。
- 输入错误立即结束本轮，原因显示为 `WRONG`；不自动播放完整答案，避免掩盖错误位置。
- 答对一项可立即给出短暂视觉反馈和进度变化；不在每次输入时写 Flash。

### 4.4 按键语义

| 状态 | `UP` 短按 | `DOWN` 短按 | `OK` 短按 | `OK` 长按 |
| --- | --- | --- | --- | --- |
| 准备 | 轻反馈，不改设置 | 轻反馈，不改设置 | 开始一局 | 返回主菜单 |
| 播放 | 忽略 | 忽略 | 忽略 | 中止并返回 |
| 复现 | 输入 `UP` | 输入 `DOWN` | 输入 `OK` | 中止并返回 |
| 成功过渡 | 忽略 | 忽略 | 忽略 | 返回主菜单 |
| 结果 | 不改变成绩 | 不改变成绩 | 开始新一局 | 返回主菜单 |

首版忽略 `DOUBLE` 事件。长按 `OK` 继续遵循仓库的全局返回语义；未完成的当前序列不计入
最高成绩，也不保存为可恢复的半局。

## 5. 状态模型

玩法逻辑应与 LVGL、音频驱动和 NVS 解耦，至少包含以下状态：

| 状态 | 说明 | 可迁移条件 |
| --- | --- | --- |
| `READY` | 等待开始，显示最高成绩 | `OK CLICK` → `PLAYBACK` |
| `PLAYBACK` | 设备逐项播放当前序列 | 播放结束 → `INPUT`；长按 → `READY` |
| `INPUT` | 等待用户逐项复现 | 全部正确 → `SUCCESS`；错误/超时 → `RESULT` |
| `SUCCESS` | 本轮完整通过的短反馈 | 长度小于 12 → `PLAYBACK`；长度 12 → `MAX_RESULT` |
| `RESULT` | 本轮失败结算 | `OK CLICK` → 新局；长按 → `READY` |
| `MAX_RESULT` | 达到首版上限的结算 | `OK CLICK` → 新局；长按 → `READY` |

模型只接收规范化输入和时间事件，例如 `start`、`token`、`tick`、`long_back`；它不直接
调用 `lv_*`、`bsp_audio_*` 或 `nvs_*`。

## 6. 成绩口径

为避免“当前挑战长度”和“已完成成绩”混淆，使用以下定义：

- `challenge_level`：正在挑战的序列长度。
- `clear_level`：本局最后一次完整复现的长度；首轮失败时为 0。
- `best_level`：历史上完整复现过的最大长度，范围 0–12。
- `session_count`：启动过的训练局数，可选统计。
- `correct_inputs` / `total_inputs`：可选的累计输入统计，不在首版 UI 强调。

示例：

- 长度 3 处错：`CLEAR 0`，`BEST` 不变。
- 完成长度 3，长度 4 处错：`CLEAR 3`，只有当历史最佳低于 3 时才更新 `BEST 3`。
- 完整完成长度 12：`CLEAR 12`、`BEST 12`，进入 `MAX_RESULT`。

首版主指标只有 `BEST` 和本局 `CLEAR`。不显示“智力等级”、百分位或与他人比较的数字。

## 7. 持久化与恢复

### 7.1 最小数据

使用现有 NVS 分区，命名空间建议为 `memory`：

```text
schema_version  uint8   数据格式版本
best_level      uint8   0..12
```

首版只持久化 `best_level`。亮度、声音和节奏是运行时设置，重启后恢复安全默认值；只有在产品
明确需要时再增加 NVS 字段和迁移逻辑。声音关闭或不可用时，视觉流程仍必须完整可玩。

### 7.2 写入时机

- 只在结果结算且产生新纪录时请求一次写入。
- 不在每个 token、LVGL tick 或音频片段中写 Flash。
- NVS 读取不到 key 时按 `best_level = 0` 处理。
- NVS 读写失败时继续训练，并在结果页显示 `SAVE OFF` 或 `NOT SAVED`；不自动擦除分区。
- 版本不兼容时使用安全默认值，保留日志；若将来数据结构明显增长，再引入迁移或双槽 CRC。

### 7.3 断电语义

首版不恢复未完成半局。断电或重启后回到 `READY`，历史 `best_level` 保留；正在进行的局不
计分。这使恢复规则简单、可解释，也避免保存完整序列和时钟状态。

## 8. 音频与视觉降级

- 每个 token 使用独特短音调；成功、错误和超时使用不同的短反馈音。
- 优先实时生成小块 PCM，不嵌入大音频资源，不创建长录音缓存。
- 音频播放由独立 worker task 完成；按键回调只投递事件，不能阻塞。
- ES8311 未初始化、写入失败或用户关闭声音时，视觉高亮和文字流程必须保持完整。
- 音频不是唯一正确提示：按键文字、位置、符号和进度点要能独立传达状态。

## 9. 可访问性与安全边界

- 不只用颜色区分 token；每个按键同时有 `UP`、`DOWN`、`OK` 文本和符号。
- 状态词使用高对比、稳定位置的短标签：`WATCH`、`YOUR TURN`、`GOOD`、`WRONG`、
  `TIME UP`、`TRY AGAIN`。
- 默认节奏给用户足够反应时间；设置页的慢速档只改变提示节奏，不改变序列随机规则。
- 成功和错误只做一次短反馈，不使用高频闪烁或持续刺眼动画。
- 屏幕文案不承诺治疗、提升记忆力或诊断结果。
- 训练数据默认只保存在设备本地；不采集姓名、语音、位置或网络标识。

## 10. 实现落点

首版不需要改 `components/bsp`，也不需要新增依赖或分区：

| 文件 | 职责 |
| --- | --- |
| `main/memory_model.c/.h` | 纯序列、状态、输入校验、成绩计算 |
| `main/demo_memory.c` | 页面生命周期、按键事件转发、LVGL 呈现 |
| `main/memory_store.c/.h` | NVS 读取/写入和失败降级（可先内嵌在 demo，变复杂再拆） |
| `main/main.c` | 开机页、主菜单、亮度/声音/节奏设置、时间/电量状态和退出页 |
| `tests/test_memory_model.c` | 无硬件的模型测试 |

接入现有工程时只需同步 `main/demo.h`、`main/CMakeLists.txt` 和 `main.c` 的 `DEMOS[]`。UI
复用 `ui_pixel_screen_create()`、`ui_pixel_panel_create()` 和现有吉祥物；不另造主题或页面
工厂。

生命周期必须遵守现有约束：

1. 按键回调只入队，不访问 LVGL、不播放音频、不写 NVS。
2. 音频 worker 和计时任务在页面退出前先停止并完成有界退出握手。
3. 非 LVGL 任务更新对象前持有 `bsp_lvgl_lock()`。
4. 删除 screen 前停止所有 timer/task/callback，并清空对象指针。

## 11. 自动化验收

### 11.1 主机逻辑

- 初始序列长度为 3，答对一轮会按下一长度重新生成完整序列，不继承上一轮前缀。
- 长度 12 是上限，不生成长度 13。
- 正确输入、错误输入、超时、空输入和越界输入都得到确定状态。
- 相邻 token 重复时仍视为合法随机输出。
- `PRESS + CLICK` 只计一次，`DOUBLE` 不改变模型，`OK LONG` 不留下 token。
- `best_level` 只由完整通过的长度更新，边界 0 和 12 正确。
- 重复结算事件不会重复更新成绩或写入请求。
- NVS 默认值、版本不兼容和写入失败路径可独立测试。

### 11.2 真机

- 240 × 320 屏幕上状态词、按键图例、电量和吉祥物不重叠。
- 三键短按/长按边界稳定，快速操作不丢位、不重复计数。
- 安静环境下三种音调可区分；禁用或拔除音频后仍可完成一局。
- 反复进入/退出页面无任务、timer、LVGL 对象或堆持续泄漏。
- 新纪录写入后重启，`BEST` 保留；NVS 故障不影响当前训练。
- 记录内部 RAM、最大连续空闲块和音频任务栈高水位。

## 12. 迭代顺序

1. **P0：** 顺序记忆单模式、长度 3–12、视觉/音频提示、错误/超时结算、`BEST` 保存。
2. **P1：** 慢速档、暂停/继续、上一轮复盘、可选清除成绩、更多反馈动效。
3. **P2：** 反向记忆、节奏记忆、视觉-only 模式、每日挑战和 BLE 同步。
4. **P3：** 手机/电脑配置训练内容或由 AI 生成训练包；设备端保持离线可用。

每个阶段都先验证上一阶段的稳定性，再增加新的状态或资源。不要在 P0 同时引入联网、
NFC、大图、长音频和复杂用户账户。

## 13. 首版完成定义

满足以下条件才算首版完成：

- 用户可以独立完成“开始 → 观看 → 复现 → 成功/失败 → 重试”闭环。
- 规则、成绩和超时行为与本文档一致，且有纯逻辑自动测试。
- 音频、电量计或 NVS 任一可选能力不可用时，核心训练仍可用并有明确提示。
- 真实设备上完成显示、按键、音频、重启保存和反复进出页面验收。
- 构建结果、主机测试结果和真机结果分开记录；不能把编译通过写成硬件验证通过。
